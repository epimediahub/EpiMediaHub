# EpiMediaHub Android 1.0.47 – genauer Speedtest bei HTTP 429

Dieses offizielle App-Update verbessert die Diagnose von HTTP-Zugriffsbeschränkungen beim Fire-TV-Speedtest. VPN, App-Daten und Geräteaktivierung bleiben erhalten.

- Zeigt künftig den tatsächlichen **Hostnamen** an, wenn ein Speedtestanbieter HTTP 403 oder 429 meldet. Ein solcher Fehler ist **kein Durchsatzmessergebnis**.
- Führt den Vergleich 1/2/4 paralleler Downloads bei Hetzner über **verschiedene exakt geprüfte HTTP-Dateibereiche** aus, statt viermal denselben Präfix anzufordern.
- Bei verweigertem Cloudflare-Download schaltet **nur der Speedtestserver**, nicht die VPN, auf Hetzner **HEL1 (Helsinki)** um. Wenn HEL1 ebenfalls HTTP 403 oder 429 meldet, prüft die App einmalig **FSN1 (Falkenstein)**. Danach endet die Messung mit einer eindeutigen Fehlermeldung ohne erfundenen Messwert.
- Der vorhandene 1-Gbit/s-Tacho sowie der real gemessene 1-/2-/4-Stream-Durchsatz bleiben vorhanden.
- Das Netzwerk bleibt mit dem VPN-Netz verbunden und der gesicherte Exit wird vor, während und nach Messungen geprüft. Keine stillschweigende ungeschützte Direktverbindung.
- Bei blockiertem Cloudflare-Upload erscheint weiterhin **„Upload nicht verfügbar“** statt 0 Mbit/s.

**Hinweis:** Server können Anfragen weiterhin begrenzen. HTTP 429 ist kein Beleg für einen langsamen oder ausgefallenen WireGuard-Tunnel. Die verschiedenen Testserver haben unterschiedliche Netzanbindungen; deshalb sind deren Mbps-Werte nicht exakt vergleichbar. Diese Änderung ist kein garantierter VPN-Performancegewinn.
